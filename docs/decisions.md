## 2026-11-19
- **Bridge language: Python.** Rich libraries for Moodle, Google Calendar, scheduling; easy to read.
- **AI engine: Claude Code in headless mode (`claude -p`).** Runs on the user's subscription; can resume existing sessions (`--resume`).
- **Interface: own Android app.** No Telegram for now; can be added later if needed.
- **Android app: Kotlin + Jetpack Compose.** Native access to usage stats, Health Connect, background work and notifications. UI quality is a priority.
- **App languages: English and Turkish, selectable in settings.** AI replies follow the selected language.
- **Phone ↔ computer: Tailscale private network.** Bridge is never exposed to the public internet.
- **Memory lives outside this repo, local only.** Kept in its own folder with local git (no remote) for history and undo.
- **This repo contains no personal data.** Personal settings live in a git-ignored config outside the code.
- **Language of repo and memory files: English.**
- **Sleep data: manual entry first, fallback to screen-off / first-unlock times.**
- **Workflow: planning in Claude chat, building with Claude Code on the Ubuntu machine.**

## 2026-11-20
- **Owner notifications: local only for now.** `scripts/notify.sh` prints a visible line and shows a desktop notification when available; no third-party notification service. Phone push will be added behind the same script once the app exists.
- **Commits use the hosting platform's no-reply address**, set in this repository's local git config, so no personal e-mail address enters the public history.
- **Issue dependencies are machine-checked.** `scripts/sync-blocked.py` derives the `blocked` label from each issue's `Blocked by:` line, so labels cannot drift from the dependency text.
- **Bridge framework: FastAPI on uvicorn.** Small, well documented, supports streaming responses for later; cheap to replace because the bridge is a handful of routes.
- **Bridge Python version: 3.12 or newer, using the interpreter already on the machine.** `uv` is configured never to download an interpreter, so setup needs no extra installs; newer Pythons work unchanged.
- **Bridge auth is default-deny.** A middleware rejects every path except `/health` without the bearer token, including unknown paths; API docs/schema endpoints are disabled.
- **Bind addresses are validated.** Only localhost or a Tailscale-range address is accepted; wildcard and public addresses stop the bridge at start-up.
- **Headless runs set every flag explicitly and use the CLI's restricted mode.** `/ask` runs `claude -p` with `--permission-mode dontAsk --permission-prompts none --restricted --tools Read,Glob,Grep`, strict MCP config and no slash commands, so a changed CLI default or a personal settings file cannot widen what a phone prompt may do. Confirmed with a real run: reading outside the folder is denied.
- **The Claude child process gets an allow-listed environment.** Prevents a stray API key from silently switching billing and keeps bridge secrets away from the model's process.
- **`/ask` continues only its own sessions.** A `session_id` is accepted only if it belongs to the configured ask folder; other sessions on the computer are reachable only through the sessions endpoints with their own checks.
- **Streaming is implemented** as server-sent events on the same `/ask` endpoint (`"stream": true`).
- **Concurrency: at most two runs at a time by default, one per session**; extra requests are refused immediately (429/409) rather than queued, so the phone always gets a prompt answer.
- **Session listing reads the transcripts directly, scoped to allowed folders.** The official SDK offers session-listing functions, but its package is a download of more than 150 MB that bundles a second copy of the CLI, and it enumerates every project. The bridge instead uses a small tolerant reader that opens only the project folders of allowed roots; it can be swapped for the SDK later behind the same endpoint.

Never addable: the home directory itself, system directories, hidden config or credential folders, anything outside the home directory. Every change sends a notification and is logged. - **Fixed limits on allowed folders are applied wherever the list is used**, not only when a path is added.

### Owner input recorded 2026-11-20 (connectivity)
- **The "Tailscale private network" decision is under review.** The computer is usually on a managed network whose firewall blocks the VPN (the node stays offline), the block will not be circumvented, and the system must work on that network. Candidate replacement: phone and bridge both make ordinary outbound HTTPS/WebSocket connections to a relay, with end-to-end authenticated encryption between phone and bridge so that the relay can neither read nor forge messages. ### Chat and session requirements (owner, 2026-11-20)
- **History:** the phone gets the last few exchanges of a session (default 4) and loads older ones on demand; the computer keeps the full transcript; the phone does not cache whole sessions.
- **While a run is in progress:** a new message is queued by default and can be edited or removed; an explicit force send interrupts the run and sends at once; cancel stops the run cleanly (interrupt first, terminate only if needed). File changes already made are not undone, and the app says so. Two runs never write to one session.
- **Skills and slash commands:** listed with completion when "/" is typed; enabled per session, scoped to that session's folder, only in allowed folders and only in the capable mode; the read-only default stays locked down. Every skill install needs explicit approval showing source, contents and target; skill content is untrusted until approved.
- **Model per session, with a default setting: Opus with high effort.** Available effort levels are read from the CLI; the CLI offers no documented way to list models, so the model list is the documented family aliases, configurable.
- **Files in chat:** offered as a card; transferred only on the owner's tap; sealed, chunked, deleted from the relay on delivery; saved to the system Downloads folder with no copy in the app; only from allowed folders; 50 MB per file by default.
- **The relay stays on the no-cost plan.** Realistic file use is a few percent of its allowance, and the paid plan cannot be capped for this database.
- **Interactive questions:** plain `claude -p` has no documented way to answer the question tool from a host, so questions are plain text for now. Native option cards need the Agent SDK, which is raised as a decision because it would change the logged choice to keep `claude -p`.
- **MCP servers, project hooks and project settings in capable runs are raised as a decision:** they run outside the OS sandbox, so the guardrails cannot be enforced for them.
- **Chat features, implementation choices (agent):** a message for a busy session answers `202` and waits instead of being refused; a hold on the queue after a cancel ends with the owner's next message, a hold after an error or a restart only with an explicit resume; file offers use a marker line `[[file: path]]` that only the bridge turns into a card; hidden files are never offered; the history cursor is a position in the transcript; the bridge's own runs use the default model unless a background model is set.

### Implementation choices for the SDK runner (agent, #104; cheap to change)
- **Own transport, not the SDK's launcher.** The SDK's launcher passes the bridge's whole environment to the child (options can only add variables) and falls back to its bundled Claude Code. The bridge starts the installed `claude` itself, with the allow-listed environment and the same flags as `claude -p` runs, and uses the SDK for the protocol (client, messages, interrupt). Whether the new chat keeps the old chat's permission to change files is the owner's choice (#188); until then it starts read-only.
- **Lean guardrail checks, built (#181).** Capable runs need the SDK runner; `claude -p` keeps read-only runs only and has no check. The marker keeps the versions it verified but a version change no longer invalidates it: a new Claude Code or SDK version (or a newer core version) starts the core set at once, on the routing job `guardrail_check` (default `haiku`, never moved by the background model setting). The full suite runs with `scripts/verify-guardrails --full`, or by itself at most once in 30 days between 03:00 and 06:00 with nothing running. Only a failed probe switches capable mode off (and is final for that version key); inconclusive probes, failures of the check's own environment, crashes and timeouts change nothing and are retried three times, 30 minutes apart. A core pass alone never switches the mode on.
- **The core set (#181)** covers the sandbox probe script (no writes outside the run's folders; private settings, bridge token, keys and SSH keys unreadable; no sudo; no secrets in the environment; the network probes), the file tools, the audit log, the gate's approvals, the approval escape, the model-free checks, the chat-folder block and the program-folder block (about 9 runs). On `haiku`: core 116/116 probes passed, full suite 240/240, no inconclusive; a control run with an unsafe allow-list failed as it must.
- **Open network, built (#182).** Claude Code's sandbox keeps the filesystem rules; its network allow-list is one wildcard per top-level domain (IANA list shipped as `tlds.txt`), because a bare `*` let commands reach the computer itself (bridge port, adb) through the proxy in every address spelling. With the list, IP addresses and names that resolve to loopback are refused; names of other private-network hosts may still be tried. Web tools (WebFetch, WebSearch) are offered; the gate refuses WebFetch to any host that is not public. Capable runs get the open network only after a check at the current core version showed it (`open_network`).
- **GitHub access in runs (#182).** The bridge reads the owner's `gh` token outside the sandbox and passes it as masked variables (`GH_TOKEN` and a pre-encoded git header); commands see a placeholder and the sandbox's proxy puts the real value in only for GitHub's hosts. GitHub SSH addresses are rewritten to HTTPS. Nothing from the `gh` or git settings or the keyring is readable. `Read(//proc/**)` is denied.
- **Approvals with the open network (#182).** Cards for deleting, force, pushing, installing and sending stay; the gate's network category is gone, so downloads and `gh`/`git` reads run freely; `gh` commands that change something on GitHub are asked like a push; a push of the memory folder is refused without a card. The bridge-run push of #178 (`netpush`) is removed.
- **Updates without a card, built (#183).** `[[apply-update]]` in the answer to a message the owner sent starts the applier at once ("update started"); every other check stays (wait until no run is active, commit, tests, lint, build and register, restart) and the owner is notified of the outcome. New refusal: `not_owner`.

### Implementation choices of the thirteenth round, continued (agent; cheap to change)
- **Scores (#206).** Each part is 0-100, pure functions in `activity/Scores.kt`; a part without data has no score (never 0) and the day's score is the mean of the parts that have one.
  - **Sleep** = 70 % length + 30 % regularity; length alone until three other nights of the seven mornings before are known. Length: 100 between 7 and 9 hours, linear to 0 at 4 and at 12 hours.   - **Words:** Good from 80, Fair from 60, Low from 40, else Very low. Today is labelled "so far". Colours: sleep violet, digital peach, tasks sky; each part always carries its icon, name and number.
